# Личный кабинет GateX (Telegram Mini App)

Кабинет открывается из бота @gatexvpn_bot. Пользователь видит статус подписки,
ссылку для Happ и пошаговую настройку. При первом входе кабинет сам ведёт по шагам:
установить Happ → добавить подписку одной кнопкой → включить VPN.

Демо на примерных данных: `python3 cabinet/scripts/build_preview.py preview.html`
и открыть файл в браузере (переключатель «Демо-данные» вверху справа).

## Что внутри

| Путь | Что это |
|---|---|
| `web/` | Сам кабинет: `index.html`, `app.css`, `app.js`, без сборки и фреймворков |
| `web/open.html` | Передаёт ссылку `happ://add/…` системе (Telegram сам открывает только http/https) |
| `web/vendor/qrcode.js` | Генератор QR-кодов (qrcode-generator 1.4.4, MIT) |
| `server/app.py` | Бэкенд на aiohttp: раздаёт `web/` и отвечает на `POST /api/me` |
| `deploy/` | systemd-юнит и кусок конфига nginx |

### Экраны
- **Главная**: статус (активна / скоро закончится / закончилась / нет подписки), дата окончания, трафик, устройства «2 из 3», последнее подключение, кнопки «Продлить» и «Установка и настройка».
- **Настройка**: мастер из трёх шагов под устройство (iPhone, Android, Windows, macOS, Linux, ТВ). Для другого устройства показывает QR-код и кнопку «Себе в Telegram».
- **Профиль**: имя и ID, **мои устройства** (модель, система, приложение, последняя активность, кнопка «Удалить» с подтверждением), основная и резервная ссылки подписки, продление, рефералка, канал, повтор обучения.
- **Помощь**: частые вопросы (включая белые списки и сервер «🇵🇱 Обход БС») и связь с поддержкой.

Тема следует теме Telegram (тёмная или светлая). Флаг «обучение пройдено» хранится
в Telegram CloudStorage и localStorage, поэтому на втором устройстве приветствие не повторяется.

## Откуда данные

Оба запроса несут `initData` от Telegram, подпись проверяется токеном бота (HMAC, срок 24 часа).

`POST /api/me`:
1. Ищем пользователя в Remnawave: `GET /api/users/by-telegram-id/{id}`. В Remnawave 3.x этого маршрута нет, тогда читаем `GET /api/users` постранично и фильтруем по `telegramId` (список кешируется на 60 секунд). Если записей несколько, берём активную с самой поздней датой.
2. Устройства: `GET /api/hwid/devices/{key}`, где key — `uuid` (2.x) или числовой `id` (3.x).
3. Отдаём статус, дату, трафик, лимит устройств, ссылки подписки и список устройств. Ответ кешируется на 30 секунд.

`POST /api/devices/delete` с `id` устройства удаляет его навсегда. Сервер заново читает устройства пользователя
и находит своё (чужое так не удалить: id сверяется только со своим списком), затем:

1. просит бота занести HWID в чёрный список (`BOT_REVOKE_URL`, `POST {initData, hwid}`): прокси подписки
   на FR отдаёт такому устройству заглушку и не пускает его в панель, поэтому после «Обновить» в Happ оно
   не добавляется обратно. Если бот не ответил 200, ничего не удаляется и странице уходит 502;
2. удаляет HWID в панели: `POST /api/hwid/devices/delete` (`userUuid` в 2.x, `userId` в 3.x);
3. меняет ключи пользователя: `POST /api/users/{id}/actions/revoke {"revokeOnlyPasswords": true}`.
   Ссылка подписки та же, но конфиг, уже скачанный на удалённое устройство, перестаёт работать.
   Остальные устройства получают новые ключи при следующем обновлении подписки в Happ.
   Выключается `REVOKE_KEYS_ON_DELETE=0`.

Удалённое устройство само не вернётся, но его можно вернуть вручную: раздел «Удалённые устройства» в профиле.
`POST /api/devices/removed` берёт список у бота (`…/api/devices/revoked`), `POST /api/devices/restore` с `id`
снимает блок (`…/api/devices/restore-hwid`). Оба адреса бота — соседи `BOT_REVOKE_URL`. После возврата на
устройстве нужно обновить подписку: ключи с момента удаления сменились.

UUID пользователя и сырые HWID на страницу не попадают, вместо HWID отдаётся хеш.
Удаление устройства — единственная запись в панель.

## Тарифы (с 17.10.2026)

Цены, пакеты устройств, скидки и теги лежат в `server/plans.py`. Тот же файл скопирован в бота
(`/root/vpn_bot/plans.py`), чтобы кабинет и бот считали одинаково.

- Тариф хранится тегом пользователя в Remnawave: `ECO`, `ECO_BS`, `FAMILY`, `FAMILY_BS`, `TRIAL`.
  Пользователь без такого тега — на старом тарифе. Новые тарифы покупают все: старый тариф работает
  без изменений до конца оплаченного срока, оплаченные дни добавляются к нему, а новый тариф
  (устройства, сквады, тег) бот включает в дату окончания старого.
- `/api/me` отдаёт `tariff` (null для старого тарифа) и каталог `plans`. На главной у всех белая кнопка
  «Купить подписку»: тариф, обход БС, число устройств, срок, способ оплаты.
- `POST /api/pay` (`plan`, `bypass`, `devices`, `months`, `method` = `sbp`|`crypto`): кабинет проверяет заказ
  и пересылает его боту на `BOT_PAY_URL` (`/api/plan/pay`). Бот сам проверяет initData, пересчитывает цену,
  создаёт платёж Platega и после оплаты выставляет срок, лимит устройств, сквады и тег.
- Ссылка на оплату открывается отдельной кнопкой «Перейти к оплате» по нажатию: Telegram не даёт
  открыть ссылку из кода без жеста пользователя, из-за этого раньше «не открывалось окно Platega».
- После возврата со страницы оплаты кабинет сам перечитывает подписку (`fresh: true`) и показывает «Оплата прошла».
- Бот открывает покупку сразу: `CABINET_URL&open=buy` (или `startapp=buy`).
- Файлы страницы отдаются с `Cache-Control: no-cache`, чтобы после деплоя Telegram сразу брал новую версию.

## Запуск

```bash
python3 -m venv /opt/gatex-cabinet/venv
/opt/gatex-cabinet/venv/bin/pip install -r cabinet/server/requirements.txt
cp cabinet/server/.env.example cabinet/server/.env   # заполнить BOT_TOKEN, RW_API_TOKEN
cd cabinet/server && set -a && . ./.env && set +a && /opt/gatex-cabinet/venv/bin/python app.py   # 127.0.0.1:8095
```

Предлагаемая схема на проде (ещё не развёрнуто):
1. Код в `/opt/gatex-cabinet` на FR (там же панель, API на `127.0.0.1:3001`).
2. `deploy/gatex-cabinet.service` → `/etc/systemd/system/`, `systemctl enable --now gatex-cabinet`.
3. `deploy/nginx-cabinet.conf` в server-блок `app.fast-cloude-cdn.online`, `nginx -t && systemctl reload nginx`.
4. В @BotFather: Menu Button → `https://app.fast-cloude-cdn.online:8443/cabinet/` (или кнопка с `web_app` в боте).
