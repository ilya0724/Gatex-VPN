# GateX 1.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship GateX 1.4: compact no-scroll home, landscape desktop window, sticky «Авто» without Russian exits, reconnect on network change, and full user routing (per-app on Android/Windows/Linux, own rules, presets, import/export).

**Architecture:** Routing lives in one serialisable model (`RoutingSettings`) persisted by `Settings` and turned into Xray rules by `config_builder.dart`; Android applies the per-app part through `VpnService.Builder`, desktop through Xray `process` rules. «Авто» stops being an Xray `leastPing` balancer: the app picks one server with a sticky, testable picker and re-picks on health-check failure or network change.

**Tech Stack:** Flutter (Dart ^3.13.5), Kotlin `VpnService`, gatex-core (Go, Xray-core pinned in `core/go.mod`), GitHub Actions `.github/workflows/app.yml`.

**Spec:** `docs/superpowers/specs/2026-11-05-app-routing-compact-design.md` (+ previews `preview-full.html` in `C:\Users\ilyab\.ssh\gatex-app-design\.superpowers\brainstorm\1340-1793908117\content\`).

**Base:** branch off tag `v1.3.0` (branch `claude/project-thread-8mignn`; `main` has no app code). New branch: `gatex-1.4`.

## Global Constraints

- Look stays as v1.3.0: palettes «Зелёная / Чёрная / Белая» (`ui/theme.dart`), fonts Manrope/Unbounded, `GlassCard`, `ConnectButton`, `FlagBadge`. No new visual style.
- Icons: Material Icons Rounded only (`Icons.*_rounded`); no emoji in app chrome. Server names keep `✨️ 💫 🏳` as sent; only the leading flag emoji becomes `FlagBadge`.
- Everything listed in spec §6 keeps working unchanged (themes, import, refresh, «Продлить», servers screen sorting/LTE group/«Скопировать для поддержки», diagnose, «Журнал», autoConnect, DNS, IPv6, launchAtStartup, closeToTray, tray menu, remove subscription, links, update check).
- User-Agent format `GateX/<версия>` unchanged; release asset names unchanged (`GateX-Setup.exe`, `GateX-arm64.apk`, `GateX.apk`, `gatex_amd64.deb`, …).
- Routing from the subscription (`Server.routing`) is NOT applied. Defaults: all apps through VPN, «Российские сайты напрямую» ON, «Блокировать рекламу» OFF, no own rules.
- Rule order: private CIDRs + server IPs direct → app/process mode → own rules (enabled, in order) → ads block → RU direct → catch-all.
- Apps outside VPN by mode always go direct; own rules and ads apply only to traffic inside VPN.
- «Авто» never uses a server whose `Server.flag` is 🇷🇺 and never shows the panel's own «Авто» entry.
- Old `set.directRu` value migrates into the new model on first read.
- Version `1.4.0+7` in `app/pubspec.yaml`.

## Review Focus

1. Subscription with only RU + panel-«Авто» servers → «Авто» has no candidates; expect a clear error «Нет серверов для Авто, выберите сервер вручную», not a crash or a silent RU pick (test in Task 4).
2. Network flaps twice within seconds (Wi-Fi off/on) → exactly one reconnect in flight, VPN ends connected (test in Task 5 for the debounce).
3. «Только выбранные» with an empty app list → Android `Builder` would route everything; expect the mode to be refused at save with «Выберите хотя бы одно приложение» (test in Task 1).
4. Import of garbage / other app's text → error message, current rules untouched (test in Task 1).
5. Tiny phone (360×640) and min desktop window → home still has no scroll extent and no overflow (test in Task 9).

### Task 12: In-app update like Telegram (Илья 07.11)

**Files:**
- Modify: `app/lib/state/updates.dart` (source + download + install), `app/lib/state/app_state.dart` (update state machine), `app/lib/ui/home_screen.dart` (`_UpdateBanner`), `app/lib/core/android_core.dart` + `MainActivity.kt` (channel `installApk`), `AndroidManifest.xml` (REQUEST_INSTALL_PACKAGES + FileProvider), `app/android/app/src/main/res/xml/` (file_paths), `app/packaging/windows/gatex.iss` (relaunch after silent install)
